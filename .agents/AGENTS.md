# ワークスペース専用ルール（行動指針）

<RULE[workspace]>
## 1. タスク管理と自律行動の制限
* **過去コンテキストの推測禁止:** 会話履歴や過去の要約（サマリー）に残っている古い指示や未完了に見えるタスクであっても、現在の会話文脈に直結しない限り、ユーザーの明示的な許可なく勝手に推測して再開・実行しないでください。
* **確認の徹底:** アサインされた直近のタスクが完了した場合、勝手に次の作業を探すのではなく、必ずユーザーに対して「現在のタスクが完了しました。次は何に取り掛かりますか？」と指示を仰いでください。
* **タスク状態の厳格な認識:** 行動を起こす前に、自分が今「どのタスクを実行するよう指示されているか」を常に確認し、指示の範囲を逸脱しないようにしてください。

## 2. フロントエンド実装における堅牢性（バグ再発防止）
* **曖昧なCSS高さ指定の禁止:** 親要素の高さが `aspect-ratio` 等で暗黙的に決まっている場合、絶対配置の子要素に対する `height: 〇〇%` や `margin-top: 〇〇%` の指定は（Safari等の仕様解釈の違いによるレイアウト崩れを防ぐため）禁止します。代わりに、`padding-top` を用いた幅基準のハックや、JSでの絶対ピクセル（`px`）算出など、数学的かつ仕様的にブレない手法を最優先してください。
* **SVGアセットとコンテナの役割分離:** ステージやコンテナ内でサイズ可変となるSVGアセットを生成・編集する際は、必ず大元を標準的な比率（例：`viewBox="0 0 100 100"` 等の正方形）で作成し、必要に応じて `preserveAspectRatio` を設定することで、コンテナ側（CSS）の変形に正しく追従する設計にしてください。
* **枯れた技術（後方互換性）の優先:** コンテナクエリ（`cqw`）や最新の擬似クラスなど、モダンすぎるCSS機能はモバイル端末（特に古いiOS Safari）で意図通りに動かないリスクが高いため、原則として使用を避けてください。
## 3. テスト実行の義務化
* **テストの事前実行:** コードを変更・改修した際は、作業完了をユーザーに報告する前に必ず自動テスト（`npm test` や `pytest` 等）を実行し、デグレ（既存機能の破損）がないか検証してください。テストをパスしない限り完了報告は禁止です。
